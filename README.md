# pdfx — PDF 编辑与扫描件 OCR 工具

统一处理**结构化 PDF**（有文本层）和**扫描/图片型 PDF**（没有文本层）的本地工具。
既能给人用（Web 可视化编辑器），也能给 AI 用（CLI + JSON、HTTP API、Python）。

核心能力：新建/导入、页面增删移动、文本框/手写笔迹/图片的增改删、全文检索与 OCR。

---

## 0. 只想立刻用起来

双击项目根目录的 **`启动PDF工具.bat`** 就行（Windows）：

| 操作 | 结果 |
|---|---|
| 双击 | 启动空白编辑器，浏览器自动打开 `http://127.0.0.1:8765/` |
| 把 PDF 拖到 bat 图标上 | 直接打开那个 PDF |
| `启动PDF工具.bat -check` | 只做环境自检（Python / PyMuPDF / Flask / 端口），不启动 |
| 关闭黑色窗口 | 停止服务 |

bat 自己会切到脚本所在目录找代码，所以**整个目录可以随便搬家**。
默认端口 8765，要改就编辑 bat 顶部的 `PORT=`（改完窗口会提示端口被占用就直接打开已有的那个）。

`.bat` 是 **GBK 编码 + CRLF 换行**，这是故意的：cmd.exe 按字节偏移读批处理，
UTF-8 中文会导致行错位（报 `'xx' is not recognized`）。
要改脚本内容请编辑 `tools/launch.bat.src`（UTF-8），然后运行：

```bash
python tools/build_bat.py
```

想要桌面图标：右键 bat → 发送到 → 桌面快捷方式；
再把常用的 PDF 直接拖到快捷方式上也能打开。

## 1. 它解决什么

普通 PDF 库只对"有文本层"的 PDF 有效。现实里大量文件是扫描件 —— 普通库读不出字、更改不了字。
本工具把两类 PDF 压缩成**一套 API**：

| 环节 | 结构化 PDF | 扫描件 PDF |
|---|---|---|
| 判定 | 位图覆盖率 < 50% 且有文字 | 位图覆盖率 ≥ 50% |
| 读文本 | 直接读文本层（毫秒级） | **按需** OCR：浏览时不识别，点「识别本页」或检索/导出时才跑（结果按图像指纹缓存） |
| 改文本 | `redaction` 真删原字 → 按原字号/颜色重绘 | 用页面底色**覆盖**原像素 → 重绘新字 |
| 删文本 | 真删（保留图像与矢量图形） | 画背景色块盖住 |
| 检索 | 文本层匹配 | OCR 行匹配 + 忽略空白/全半角差异 |

上层调用完全一致，**调用方不需要判断页面类型**：

```python
d.update_text(0, "p0:o57,429", "新内容")   # 扫描页
d.update_text(1, "p1:t56,300", "新内容")   # 结构化页
```

判定看的是**位图覆盖率**而不是"有没有字"：扫描页被插入新文本后仍然是 `mixed`，
检索照样会 OCR，不会因为多了几行文字就丢掉原图内容（这是很多工具踩的坑）。

> **OCR 开不开只由你决定。** 早期版本只要判定是扫描页就整页识别，翻一页等 1~3 秒，
> 连续模式滚下去一路卡。现在浏览只读文本层，扫描页显示为"未识别"；
> 需要文字时点**顶栏右侧的「本页 OCR」开关**（或右侧对象面板的「识别本页」），
> 或直接检索/导出全文（这两个动作会自动识别）。
> 开关上直接写着当前状态：`本页 OCR 关` / `本页 OCR 开` / `本页 OCR 待刷新`。
> 识别结果按「页面图像指纹」缓存，同一页只算一次。
>
> 识别过以后，按钮变成**「收起识别」**——再点一次才关掉；程序不会自己开，也不会自己关。
> 改了内容（插字、画笔、拖图）时，旧识别框和画面可能对不上，界面**只提示、不动开关**：
> 对象列表顶部出现「这一页改过内容，识别框可能偏了」，你可以点「刷新识别」重算、
> 点「收起」关掉，或者什么都不做继续用旧框。重算要 1~3 秒，所以不自动跑。

## 2. 三种用法

### 2.1 可视化编辑器

```bash
python -m pdfx serve 报告.pdf --port 8765
# 浏览器打开 http://127.0.0.1:8765
```

> **改过代码后必须重启服务**：前端是静态文件，刷新浏览器就能拿到新版；但后端不会。
> 新前端会先请求 `/api/caps` 握手，如果对端是旧进程，页面顶部会出现红色提示条，
> 告诉你关掉窗口重新启动 —— 避免"明明改了却没生效"的困惑。

界面分四块：

| 区域 | 内容 |
|---|---|
| 左侧上 | **文档栏** —— 本次会话里打开/新建的所有文档，点击切换；有未保存改动的显示红点 |
| 左侧下 | **页面缩略图** —— 固定高度、按比例居中的真实预览，下方标页码，标题处显示「当前页 / 总页数」 |
| 中间 | **画布** —— 三种浏览方式（见下），可缩放、拖动 |
| 右侧 | 对象 / 属性 / 结果 三个面板 |

**三种浏览方式**（顶栏右侧三个小图标）：

- 单页：只渲染当前页，上下滚动查看页内内容
- 连续：所有页纵向堆叠，上下滚动即翻页，滚动时自动同步当前页
- 横向：所有页左右并排，左右滚动翻页

**画笔手感怎么保证的**：画布分两层 canvas —— `base` 放已提交内容（历史笔迹、文本块、搜索命中、选中框），
`live` 只放"正在进行的操作"。拖动时只清空重绘 `live`，开销与页面上已有多少笔画无关；
指针事件还做了两件事：`pointerdown` 时缓存一次 `getBoundingClientRect()`（避免每帧强制布局），
用 `requestAnimationFrame` 把高频移动合并成每帧一次重绘。松手时先把这一笔写进本地状态再异步落库，
所以不会有"线闪一下"的空档。橡皮同理：拖动时按"点到线段距离"在本地把笔画切开，即时可见，松手才提交服务端。

**选中之后可以拖**：用「选择」工具点中文本或图片，四角四边出现 8 个手柄。
拖框内 = 移动；拖四角 = 等比缩放（文本联动字号）；拖四边 = 单向拉伸。松手才提交，过程中只有虚线预览。

页数多时连续/横向模式用 `IntersectionObserver` 懒加载，只请求视口附近的页面位图；
缩略图同理，滚到哪渲染到哪 —— 一百页的文档不会一开就发一百个渲染请求。

**剪贴板**：截图工具、浏览器里复制的图，直接在画布上 `Ctrl+V` 就插到当前视口中心
（按原比例，最大占页宽 55%），插完自动选中、可以马上拖手柄调整。
选中一张图按 `Ctrl+C` 复制：后端把该实例转成 PNG 写进系统剪贴板（PDF 里的图可能是
JPEG/CMYK，剪贴板只可靠地收 PNG），到别的程序里也能贴。剪贴板写不进去时（非安全上下文、
浏览器拒权）会退回应用内缓存，`Ctrl+V` 仍然贴得出来。

**快捷键**（顶栏最右侧的键盘图标，或按 `?` / `F1` 开关右侧「快捷键」侧栏）：

| 操作 | 键 |
|---|---|
| 保存 / 撤销 | `Ctrl+S` / `Ctrl+Z` |
| 复制选中的图片或文字 / 粘贴图片 | `Ctrl+C` / `Ctrl+V` |
| 删除选中对象（文本、图片、笔迹） | `Delete` 或 `Backspace` |
| 取消选中 / 收起侧栏 | `Esc` |
| 选择、文本、画笔、橡皮、插入图片、拖动 | `V` `T` `P` `E` `I` `H` |
| 上一页 / 下一页 | `PageUp` / `PageDown` |
| 缩放 | `Ctrl+滚轮` |
| 打开 / 收起快捷键侧栏 | `?` 或 `F1` |

侧栏是网格里的第 4 列，展开时画布跟着变窄而不是被盖住；开关状态记在 localStorage，
下次打开还是上次的样子。所有快捷键在输入框里都不生效（不抢你打字）。

拖放：PDF 拖进窗口 = 打开；图片拖进窗口 = 插到当前页（和 `Ctrl+V` 同一条路）。

### 2.1.1 为什么"翻页/编辑不卡"

架构是"后端渲染位图 + 前端 canvas 叠加"，这套路线本身没问题（本地工具里很常见），
真正决定手感的是缓存与请求编排。几处关键改动（`tools/bench.py` 可复现）：

| 问题 | 原做法 | 现做法 |
|---|---|---|
| 扫描页对象查询 | 判定为扫描页就整页 OCR，**916 ms/页** | 只在需要时 OCR + 图像指纹缓存，**24 ms/页** |
| 同一个页面反复取位图 | 每次重新渲染（40~150 ms） | 按 `(页, dpi, 修订号)` 做 LRU 缓存，**0.3 ms** |
| 缩放/翻回上一页 | 位图响应 `no-store`，永远重新下载 | URL 里带 `sid`+`rev`，浏览器可长期缓存，内容变了 URL 才变 |
| 打开文档 | 逐页判断类型（扫描件上每页 40 ms） | 只取页尺寸，类型在翻到该页时顺带给出 |
| 画一笔的撤销 | 整份 PDF 序列化当快照（50 MB 文档要几百毫秒） | 笔迹走轻量快照，撤销时重建 Ink 注释，与文档体积无关 |
| 取图片实例列表 | `get_text("dict")` 在无文字页上也要 60 ms | 先用近乎免费的纯文本探测挡掉 |

`python tools/bench.py` 会打印一组贴近使用的指标（首屏渲染 / 对象查询 / 画 10 笔 / 拖图 5 次），
改动性能相关代码后可以直接对比。

### 2.2 命令行（AI 首选）

```bash
python -m pdfx describe 报告.pdf                 # 结构总览
python -m pdfx text list 报告.pdf --page 0       # 列文本（扫描页自动 OCR）
python -m pdfx search 报告.pdf "合同金额"         # 全文检索
python -m pdfx text update 报告.pdf --page 0 --id "p0:o57,429" --text "1,200,000.00"
```

默认输出单行 JSON，失败退出码非 0：

```json
{"ok":true,"data":{"page":0,"bbox":[57.24,65.62,229.59,88.6],"text":"采购合同（已复核）"},"warnings":[]}
```

### 2.3 HTTP / Python

```bash
curl -s -X POST localhost:8765/api/search -H 'Content-Type: application/json' \
     -d '{"query":"违约金"}'
```

```python
from pdfx import PDFDocument

with PDFDocument("报告.pdf") as d:
    print(d.page_type(0))                       # text / scanned / mixed / empty
    print(d.search("违约金")["total"])
    d.add_text(0, "已复核", point=[400, 60], font_size=11, color="#c62828")
    d.save()
```

## 3. 功能矩阵：范围与交互方式

> **坐标**：全库统一用 PDF 点（1pt = 1/72 inch，A4 = 595×842），原点左上角，x 右 y 下。
> **页码**：一律 **0 基**（`--page 0` 是第一页，界面显示的"第 N 页"才从 1 开始）。

> **界面上的坐标换算与设备无关**（换机器不再出现「笔画和图片乱在一起、笔画跳位」）。
> 页面位图被 `object-fit: fill` 拉满 `.pbox`，所以叠加层、命中测试一律用
> **实测比例** `pbox 实际宽度 ÷ 该页 pt 宽度` 换算，而不是写死 `zoom × 96/72`；
> `.pbox` 宽高按同一个比例生成且不取整，位图不会被非等比拉伸。
> 指针几何在 pointerdown 缓存一次，手势中滚动按 `scrollTop/Left` 增量修正，
> 缩放 / 换页 / 展开侧栏则重新测量 —— 旧实现缓存的 rect 一直用到松手，
> 页面一滚，后面每个采样点都整体平移。
> 另外所有对象请求都带「文档 / 页 / 序号」令牌：后端单锁串行时慢页的响应晚到是常态，
> 旧实现会把 A 页的图片、笔迹写进 B 页的列表（还要把 A 页尺寸记到 B 页名下，
> 之后那一页的位图按错误比例拉伸）。现在只有最后一次、且仍属于当前页的响应能落地。

### 3.1 文档创建与导入

| | 说明 |
|---|---|
| 适用范围 | 新建空白文档、打开本地 PDF、从另一 PDF 导入页面、拖拽上传 |
| 交互 | UI：「打开」浏览目录或直接拖入窗口；「新建」建独立空白文档；「插入PDF」把另一份 PDF 的页插到当前位置之后<br>CLI：`pdfx new out.pdf --size a4 --pages 2`、`pdfx page import --src b.pdf --pages "0-2"`<br>API：`POST /api/open`、`POST /api/new`、`POST /api/upload`、`POST /api/page/import` |
| 多文档 | 每次「打开/新建」都是一份独立文档，左侧文档栏列出全部，各自独立编辑；同一路径重复打开会替换旧实例 |
| 尺寸 | `a4/a3/a5/b5/letter/legal/tabloid`，或 `"595x842"`、`[w,h]` |
| 加密 | 打开加密 PDF 需密码（Python/HTTP 传 `password`，CLI 暂未暴露） |
| 保存 | 已有路径：直接覆盖原文件（先写临时文件再原子替换）<br>新建文档：弹出「保存新文档」对话框，**显示并允许修改完整保存路径**，确认后才落盘 |

### 3.2 增：页面 / 文本框 / 笔迹 / 图片

| 对象 | 操作范围 | 可视化交互 | CLI / API |
|---|---|---|---|
| **页面** | 任意位置插入空白页，可指定尺寸和底色 | 左栏「+ 添加页」插到当前页之后 | `page add --at N --size a4 --background "#fff"` / `POST /api/page` |
| **文本框** | 点一下就插入（也可拖出想要的宽度）；支持字号、颜色、字体、对齐、行距、底色；文字自动换行并按需扩框；**中英文混排自动选内置 CJK 字体** | 选「文本」→ **在页面上点一下** → 输入内容 → 回车；插入后自动选中，可拖动和拖角缩放 | `text add --text ".." --rect x0,y0,x1,y1 --size 12` / `POST /api/text` |
| **手写笔迹** | 自由曲线，每条笔画带颜色/宽度/透明度；存为 PDF Ink 注释，**可逆**（可再次擦除） | 选「画笔」→ 底部调颜色粗细 → 按住拖动，松手即提交 | `ink add --strokes '[{"points":[[x,y],..],"color":"#f00","width":2}]'` / `POST /api/ink` |
| **图片** | 支持 PNG/JPG，按原始比例插入到当前视口中央（超宽自动缩到页面 55%）；可指定位置框。<br>**三个入口等价**：点「图片」选文件、`Ctrl+V` 粘贴剪贴板里的图（截图工具复制完直接贴）、把图片文件拖进窗口 | 选「图片」→ **选完文件立即插入**，不用先拖框；插入后自动选中，拖四角等比缩放、拖四边拉伸 | `image add --rect .. --src logo.png` / `POST /api/image` |
| **图片复制** | 选中任意图片（自己插的、PDF 原有的都行）`Ctrl+C`，转成 PNG 进系统剪贴板；到别的程序里也能贴。剪贴板写不进去时退回应用内缓存，`Ctrl+V` 仍可用 | 选中 → `Ctrl+C` → 提示"已复制图片" | `GET /api/image/raw?page=&id=`（返回 PNG）/ Python：`doc.image_png(page, id)` |

### 3.3 删：页面 / 文本 / 图片 / 笔迹

| 对象 | 操作范围 | 两类 PDF 的差异 | 交互 |
|---|---|---|---|
| **页面** | 按页码/范围删除，至少保留一页 | 一致 | 左栏「删除本页」/ `page delete --pages "1,3-4"` / `DELETE /api/page` |
| **文本** | 可按 id 精确删，也可给 bbox 按区域删；**包括 OCR 识别出的文字** | 结构化：redaction 真删，**只删这一段自己的字**——文本框压在正文上时，被框住的别人的字会先删后按原位补画（字体换成内置字体，位置字号颜色照抄）<br>扫描件：背景色覆盖 | 选中对象 → 属性面板「删除」/ `text delete --id "p0:t56,57"` / `DELETE /api/text` |
| **图片** | 按显示实例删除（同一张图多处摆放可分别删） | 两者都走 **redaction 真删**：图像从内容流移除，底下被遮住的文字会露出来。同一张图被摆在多处时共用同一个图像资源，删一处后其余落点会自动补画回去，不会连带消失 | 选中 → 「删除」/ `image delete --id "p0:i@56,500"` / `DELETE /api/image`（默认 `mode=purge`） |
| **笔迹** | **只会擦笔迹**：橡皮轨迹经过处把笔画切开，只去掉经过的部分，页面原有文字与图片分毫不动 | 一致（笔迹是独立注释层，不碰原内容） | 选「橡皮」→ 拖过笔迹 → 松手 / `ink erase --points "x,y;x,y" --radius 12` / 也可 `--bbox` 框选整条擦 |
| **页面原有内容**（仅 CLI / AI 提供，界面橡皮不提供） | 抹掉页面本身的像素：命中的文字真删（结构化页 redaction，删完检索不到），图像内容按纸色涂掉（扫描件上的手写字、印章）。**不可逆**，只能在撤销栈里回退 | 结构化：文字真删 + 涂纸色<br>扫描件：涂纸色（纸色取擦除区周边众数色，不会留明显白块） | CLI：`erase --points "x,y;x,y" --radius 12` 或 `--rects "x0,y0,x1,y1;..."`（命令行本身就是显式调用）<br>API：`POST /api/erase` **必须带 `allow_content: true`**，不带时只切笔迹<br>Python：`doc.erase_area(page, points=…\|rects=…)` |

### 3.4 改：文本与图片

| 对象 | 操作范围 | 交互 |
|---|---|---|
| **文本** | 改内容、字号、颜色、字体、对齐。**结构化页保留原样式**（字号/颜色/字体族自动继承）；扫描页自动取区域底色做覆盖。<br>新内容变长时向右扩框（不越出右边距），避免被压成多行 | UI：选中文字 → 属性面板改内容 → 「应用修改」<br>CLI：`text update --id .. --text ".." [--size 12 --color "#c00"]`<br>API：`PUT /api/text` |
| **文本的位置/大小** | **移动**（不改内容）或**缩放**（字号跟着框走）。<br>**目标框是硬边界**：字号放不下就在框内缩小，绝不会把字画到框外（早先是把绘制框往下撑 1.8 倍，字直接压到下面的正文上）。<br>只拖左右边 = 纯重排，字号不变、框往下长。<br>多行文本框在文本层里是一行一条，会按内容合并成**一个**对象，拖动/删除都是整体。<br>原位置会被真正抹除，不留残影；**而且只抹自己**——文本框压在正文上时，底下的字不会被顺手带走。<br>两类 PDF 都适用 | UI：选中后拖动 = 移动，拖四角 = 等比缩放，拖四边 = 改宽度自动换行<br>API：`PUT /api/text` 传 `{page, id, rect, font_size?}`（返回里 `fitted=false` 表示框小到 4pt 都放不下）<br>Python：`doc.transform_text(page, id, rect=[x0,y0,x1,y1])` |
| **图片** | 「替换内容」（保持位置）、「移动/缩放」（保持内容）、「单向拉伸」三件事。<br>移动/缩放会先盖掉原位置再在新位置重绘，等比由 `keep_ratio` 控制 | UI：选中图片 → 「替换图片」；拖动 = 移动，拖四角等比、拖四边拉伸<br>CLI：`image replace --id .. --src new.png`<br>API：`PUT /api/image` 传 `{page, id, rect, keep_ratio?}`<br>Python：`doc.transform_image(page, id, rect, keep_ratio=False)` |

### 3.5 查：全文检索与导出

| | 说明 |
|---|---|
| 范围 | 全部页或指定页；支持正则；支持强制 OCR |
| 一致性 | 结构化页走文本层（快、准）；扫描页走 OCR（首次约 0.5~2 秒/页，之后命中缓存）。**两类的返回结构完全相同** |
| 容错 | OCR 常把 `1,038,000` 拆成 `1，0 3 8，0 0 0`、把 `-` 认成 `·`，检索时自动做「忽略空白 + 全半角 + 分隔符折叠」匹配；单行没命中会自动尝试跨行拼接 |
| 返回 | 每命中含 `page / bbox / text（整行）/ match（命中片段）/ source（text|ocr）/ score / context` |
| 交互 | UI：顶部搜索框回车 → 结果面板点击跳页并**黄色高亮**（长行按字符比例收窄高亮框）<br>CLI：`pdfx search a.pdf "词" --pages "0-2" --regex`<br>API：`POST /api/search` |
| 导出 | `pdfx extract a.pdf --ocr -o full.txt`，或 `POST /api/extract` |

## 4. 设计要点

**统一的对象模型**。文本、图片、笔迹都被归一成带 `id + bbox + source` 的对象：

```json
{"id":"p0:o57,429","page":0,"bbox":[56.5,429.1,263.5,440.6],
 "text":"质保期为验收合格之日起 12 个月。","source":"ocr","score":0.95}
```

`source` 区分 `text`（原生文本层）/ `ocr`（识别）/ `user`（用户插入）。编辑时按 `source` 选择底层动作，
调用方不用关心页面类型。

**状态内嵌进 PDF**。用户插入的文本、图片、笔迹元数据存在 PDF 的自定义键 `PDFXState` 里
（不是旁挂 JSON），文件改名、移动、发给别人都不会丢。

**id 可解析**。id 里编码了坐标（`p0:t56,57`），换个进程重新打开也能定位到同一个对象；
用户插入的对象用短哈希，跨编辑稳定。

**OCR 后端可插拔**，按 `RapidOCR → Windows 系统 OCR → Tesseract` 依次探测
（探测在子进程里做，避免 ONNX 运行时崩溃拖死主进程），结果缓存 7 天。都不可用时
自动降级为「只处理文本层」，其余功能照常。

**行片段重组**。OCR 常把一个长行按水平间隙切成好几段（金额、编号最容易被切），
`_merge_fragments` 会按 y 轴聚类把它们拼回一行，否则检索会漏。

## 6. 已知限制

- **扫描件"改字"是覆盖，不是真删**。原像素仍在文件里，放大或用取色工具仍可能看出痕迹。
  有法律效力的文件应重新生成，而不是涂改。
- **覆盖色来自区域边缘的众数颜色**。纯色底纸效果好；照片、渐变、复杂底纹会有色差，
  可用 `--background "#f5f5f5"` 手动指定。
- **OCR 不保证 100% 准确**（中文打印体约 95%）。改字前务必先看清楚 `text` 原文，
  否则会把识别错的字当成要改的字。形近字是主要错误来源（元/兀、0/O）。
- **同一张图摆多处的处理方式**：它们共用同一个图像资源（xref），redaction 按资源删，
  所以删/移其中一处时，程序会先把其余落点记下来、删完按原 bbox 补画回去。
  补画出来的实例在内容流末尾，层级会比原来靠上一层（叠在同区域文字之上）。
- **撤销栈在内存里**，最多 8 步；保存后重新打开不可再撤销保存前的状态。
  笔迹类操作只记"改动前的笔迹数组"（不序列化整份 PDF），所以大文件上每画一笔也不会卡；
  其余操作仍是整份快照，撤销回退的是当时那份文档。
- 加密 PDF 需要密码；CLI 尚未暴露该参数（用 Python/HTTP）。

## 7. 自测

```bash
python tools/make_samples.py     # 生成三类样本（结构化 / 扫描 / 混合）
python tools/selftest.py         # 端到端 79 项，纯 Python API
python tools/api_smoke.py        # HTTP 33 项，自动起停独立服务
node   tools/uitest.mjs          # 界面 95 项，真实浏览器点击/拖拽/触摸（需 node 18+ 与 Edge/Chrome）
python tools/bench.py            # 性能基准（不是断言，用来看数字有没有退化）
```

- `selftest.py` 按「创建与导入 → 增 → 改 → 删 → 查 → 保存/重开/撤销 → 删图重插/OCR 按需/渲染缓存 → 异常处理」
  分段跑，全部断言通过即环境可用。改动代码后应当跑一遍。
- `api_smoke.py` 在 `tmp/smoke/` 的副本上操作（结尾会 `/api/save` 写回当前文件），
  不会污染 `samples/` 里的正式样本；不带参数时**自己起一个随机端口的服务**，
  不会去连你可能正在用的 8765 实例。
- `uitest.mjs` 用 CDP 驱动无头 Edge，真派发 PointerEvent 测「新建 → 画笔 → 流畅度 →
  撤销 → 橡皮即时切断 → 文本框插入/移动/缩放 → 图片直接插入/缩放/整体拖动/无残影 →
  删图后重新插入 → 三种视图 → 文档切换 → 另存为对话框 → 插入 PDF → 橡皮只擦笔迹（正文分毫不动）→
  触摸书写 → 剪贴板粘贴/复制 → Delete 键删除 → 快捷键侧栏 → OCR 手动触发 →
  跨设备一致性（DPI / 手势中滚动 / 并发翻页）」，截图写到 `tmp/shots/`。
  几条专门的守门断言：
  - `elementFromPoint` 检查画布没被其他元素遮挡 —— DOM 里存在不等于用户看得见
  - 书写过程中 `base` 层像素数**完全不变**、`live` 层有内容 —— 这是"分层重绘"的直接证据
  - 页面已有 9 条笔迹时，200 次指针移动的处理耗时要 < 200ms —— 这是"跟手"的量化形式
  - 触摸模拟下 `pointercancel` 必须为 0 —— 一旦浏览器把手势当滚动抢走，画笔只剩两个点、橡皮完全不响应
  - 图片中心压着正文时，拖动后位移必须 > 8pt 且属性面板仍显示「位置/尺寸」而不是「文本内容」
    —— 命中若按面积挑最小对象，拖的会是底下那行小字
  - 图片移动后原位不能出现「整片实心蓝块」（按 8×8 小块统计密度，排除新旧位置重叠区）
    —— 样例 PDF 自带蓝色波浪线，单看蓝色像素占比会误判；后端若拿图片自己的颜色涂原位，
    等于没涂，会留下一个一模一样的残影
  - 「移动后原位无残影」另有一条纯后端断言：把原位置与「从没插过图时的页面」逐像素比对，
    平均差必须 < 8（实测 0.0）
  - 删除图片必须是 `mode=purged`（redaction 真删），并且删完还能再插回来、新图真的落到页面位图上
    —— 只涂一块色块的话，旧图仍在内容流里，再插新图会被按位置误判到旧处，表现为"插不进来"
  - 界面点「删除」按钮走的就是默认路径（不带 mode），接口默认值必须也是真删
    —— 底层默认改了、接口默认没改，是这一条最容易漏掉的地方
  - 同一张图插两次、删掉其中一个，另一个必须还在（后端断言）
  - `Ctrl+V` 之后对象列表必须多一张，且这张图真的画进了页面位图（不是只有一条记录）
  - `Ctrl+C` 必须有反馈；随后一次空剪贴板的 `Ctrl+V` 要能再贴一张（应用内兜底路径）
  - Delete 键删完，用户图片数量必须少一个（不断言删的是哪一张：两张粘贴图可能重叠）
  - 快捷键侧栏必须列出复制/粘贴/删除/撤销四条，展开时面板宽度 > 200px，`Esc`/`?`/`F1` 都能开关，
    开关状态写进 localStorage；展开后 canvas 内部像素尺寸必须跟新的 clientWidth 对齐
    —— 只改 CSS 宽度不重设位图，选框会被横向拉伸
    —— 两处共用同一个图像资源，redaction 删资源会把两处一起抹掉
  - 打开扫描件时对象列表里**不能出现 OCR 行**，点「识别本页」之后才允许出现
  - 顶栏必须有可见的「本页 OCR」开关，状态跟着切换：关 / 开 / 待刷新
  - 文本框压在正文上时，**移动或删除文本框后正文必须还在**（而且要恰好一份，不能重复），
    否则就是 redaction 把框里别人的字一起删掉了
  - 识别过后改内容：**OCR 行必须还在**（开关是用户的，程序不许自己关），按钮变「刷新识别」，
    列表顶部出现「刷新识别/收起」提示；过期行选中时「应用修改/删除」必须禁用；
    点刷新后提示消失、点「收起识别」后 OCR 行才归零
  - 橡皮扫过正文之后，页面深色像素数、文本条数都必须**完全不变**，只有笔迹被切断
    —— 曾经把「擦页面内容」做进界面，误扫一遍就把正文真删了，redaction 不可逆
  - `deviceScaleFactor` 分别设 1 / 1.25 / 1.5 / 2，在同一个屏幕位置画一笔，
    落库坐标误差必须 < 1.5pt 且四种 DPI 完全一致 —— 换设备不该改变落点
  - 手势中间把页面滚 80px：落笔的第一个点必须原地不动，后续采样点必须跟着页面下移 80px
    —— 旧实现缓存的 rect 不随滚动更新，后面每个点都整体跳位
  - 人为让「旧页的 `/objects` 请求」比新页晚 700ms 返回：对象列表必须仍属于当前页
    （行数、首条坐标都要对得上），且各页画布换算比例必须一致
    —— 慢设备上后端单锁串行，旧响应晚到是常态，不该把别页对象画过来
